# START_HERE — моя памятка по запуску с нуля

Моя короткая шпаргалка по развёртыванию бота. Для запуска нужны два ключа: **токен бота** и **мой Telegram ID**. Ниже я собрал, где их беру, три способа запуска и таблицу быстрой диагностики.

---

## 1. Два значения, без которых бот не стартует

### TG_TOKEN — токен моего бота

1. Открываю в Telegram **[@BotFather](https://t.me/BotFather)**.
2. Отправляю `/mybots` → выбираю своего бота (`SevastopolAiBot`).
3. Нажимаю **API Token** → копирую строку вида `123456789:AAH…` целиком.
4. Для нового бота: `/newbot` → имя → username (оканчивается на `bot`).

Это секрет: кто знает токен, тот управляет ботом. В код и в git я его никогда не вставляю.

### ADMIN_ID — мой Telegram ID

1. Открываю **[@userinfobot](https://t.me/userinfobot)** и нажимаю Start.
2. Бот присылает мой числовой ID.
3. По этому ID мне открыта команда `/admin` и приходят заявки с формы «Предложить место».

## 2. Три способа запуска

### Способ А — Google Colab (быстрая проверка без сервера)

1. Открываю `notebooks/SevastopolAI_bot.ipynb` в репозитории → кнопка **Open in Colab**.
2. В Colab слева открываю 🔑 **Secrets** и добавляю `TG_TOKEN` и `ADMIN_ID` (либо ввожу токен при запросе — ячейка спрашивает его скрытно).
3. Нажимаю ▶️ у единственной ячейки — в логах появляется «Бот запущен».
4. Остановка — кнопка ■. Colab засыпает без активности, поэтому для круглосуточной работы я использую сервер (способ В).

### Способ Б — мой компьютер

Нужен Python 3.10 или новее.

```bash
# 1. Скачиваю репозиторий (Code → Download ZIP) и распаковываю
# 2. Открываю терминал в папке проекта
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python tools/setup_env.py          # спрашивает токен и ADMIN_ID, создаёт .env, проверяет токен
python sevastopolaibot.py          # запуск: пока окно открыто — бот работает
```

`tools/setup_env.py` — мой мастер настройки: токен вводится скрытно, `.env` создаётся с правами 600, а в конце мастер проверяет токен у Telegram и пишет `✅ Токен рабочий`.

### Способ В — мой сервер, 24/7, одной командой

Подойдёт любой сервер с Ubuntu или Debian (Timeweb, Aeza, Hetzner и т. п.) с доступом по SSH.

1. На GitHub нажимаю **Code** → **Download ZIP**.
2. Закидываю архив на сервер: `scp SevastopolAIbot-main.zip root@АДРЕС:~`.
3. На сервере выполняю:

```bash
apt install -y unzip && unzip SevastopolAIbot-main.zip && cd SevastopolAIbot-main
sudo bash install.sh
```

Установщик спрашивает токен и ID, настраивает окружение и включает автозапуск. В конце он пишет «✅ Бот работает».

- **Новая версия:** распаковываю свежий ZIP и снова выполняю `sudo bash install.sh`. Паспорта и токен сохраняются.
- **Переезд с компьютера или Colab:** кладу старый `bot_state.json` рядом с `install.sh` до запуска.
- **Логи:** `journalctl -u sevastopol-ai-bot -f` (выход — Ctrl+C).

## 4. Что в логах → что я делаю

| Что видно | Что это значит | Что я делаю |
|---|---|---|
| `TG_TOKEN не задан` (код 2) | в `.env` нет токена | запускаю `python tools/setup_env.py` |
| `Unauthorized` / `401` | токен неверный или отозван | @BotFather → `/mybots` → API Token → копирую заново |
| `Promise resolution is still pending` / конфликт | запущено два экземпляра бота | останавливаю второй запуск (Colab + компьютер) |
| `Google вернул не XLSX` | таблица закрыта для чтения | Google-таблица → Доступ → «Все, у кого есть ссылка» → Читатель |
| `ADMIN_ID не задан` | пусто в `.env` | беру ID в @userinfobot и вписываю в `.env` |
| `Cannot connect to host` | нет интернета / сбой сети | проверяю сеть и перезапускаю бота |
| События не показываются | все события в таблице уже прошли | добавляю свежие события на лист «События» |
| Карточка без картинки | в «Ссылка на фото» пусто или ссылка на пост `t.me/...` | ставлю прямой адрес картинки (`.jpg`/`.png`) |
| Бот молчит, логов нет | процесс не запущен | `sudo systemctl restart sevastopol-ai-bot` |

## 5. Форма «Предложить место»: Cloudflare Worker через браузер

Заявка с моей формы `suggest.html` (`https://yurich-citycode.github.io/YuRichHUB/suggest.html`) уходит в мой Cloudflare Worker, а он пересылает её мне в личку.

1. Вхожу на **dash.cloudflare.com**.
2. Слева открываю **Workers & Pages** → **Create** → **Create Worker** → указываю имя `sevastopol-suggest` → **Deploy**.
3. Нажимаю **Edit code** → заменяю шаблон содержимым файла `worker/index.js` → **Deploy**.
4. В **Settings → Variables and Secrets** добавляю два секрета (тип **Secret**):
   - `BOT_TOKEN` — токен бота от @BotFather;
   - `ADMIN_ID` — мой ID из @userinfobot.
5. Копирую адрес воркера (`https://sevastopol-suggest.имя.workers.dev`).
6. В `suggest.html` в строке `WORKER_URL` указываю адрес воркера и сохраняю изменения.
7. Проверяю: открываю форму и отправляю тестовую заявку — она приходит мне в личку.

Если воркер временно недоступен, форма предлагает скопировать текст заявки и вставить его прямо в бота — бот распознаёт префикс `✍️ ПРЕДЛОЖЕНИЕ:` и пересылает заявку мне.

## 6. Мои правила безопасности

1. **Токен — только в секретах.** Никогда не вписываю его в код, в ячейку Colab, в переписку или на скриншот. Только `.env` с правами 600, `EnvironmentFile` systemd или секрет Cloudflare Worker.
2. **Если токен засветился — сразу отзываю.** @BotFather → `/mybots` → API Token → **Revoke** — старый токен перестаёт работать, выпускается новый.
3. **`ADMIN_ID` — тоже только в окружении.** По нему бот отдаёт статистику и присылает заявки. В коде его нет.
4. **Служебные файлы — с правами 600.** `.env` и `bot_state.json` (паспорта, XP, статистика) держу с правами 600; бот сам сохраняет `bot_state.json` с доступом только для владельца.
5. **Секреты не попадают в git.** `.env` и `bot_state.json` добавлены в `.gitignore`.
