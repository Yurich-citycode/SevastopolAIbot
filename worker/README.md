# Мой сервис заявок на Cloudflare Worker

Это мой небольшой сервис для формы `suggest.html`. Он принимает данные о новом
месте, собирает из них понятное сообщение и отправляет его мне в личку через
Telegram Bot API. Заявки приходят мне на `ADMIN_ID`.

- Я использую бесплатный план Cloudflare Workers: лимита 100 000 запросов в день мне хватает с большим запасом.
- В коде и в git нет секретов. `BOT_TOKEN` и `ADMIN_ID` я задаю как секреты Worker.
- Если секреты не заданы, POST-запрос получает `server_not_configured`.

---

## Деплой через браузер (около 10 минут)

Я могу развернуть Worker без установки программ на компьютер.

### Шаг 1. Войти в Cloudflare

1. Я открываю https://dash.cloudflare.com и вхожу в свой аккаунт.

### Шаг 2. Создать Worker

2. Слева открываю **Compute (Workers) → Workers & Pages**.
3. Нажимаю **Create** → **Create Worker** → **Deploy**. Имя можно оставить предложенное или указать `sevastopol-suggest`. Из имени получится адрес вида `https://sevastopol-suggest.<мой-сабдомен>.workers.dev`.
4. После деплоя нажимаю **Edit code**.

### Шаг 3. Загрузить мой код

5. Удаляю в редакторе код «Hello world», вставляю **весь код** из файла
   [`index.js`](index.js) этой папки и нажимаю **Deploy** справа вверху.

### Шаг 4. Добавить секреты

6. Возвращаюсь в **Compute (Workers) → Workers & Pages → мой Worker →
   Settings → Variables and Secrets**.
7. Нажимаю **Add**, выбираю тип **Secret** и добавляю две записи:
   - `BOT_TOKEN` — токен моего основного бота Sevastopol AI от @BotFather, тот же, что я использую в `.env` бота в переменной `TG_TOKEN`;
   - `ADMIN_ID` — мой Telegram ID, который я узнаю через @userinfobot. Он должен совпадать с `ADMIN_ID` у бота.
8. Нажимаю **Deploy** внизу страницы.

### Шаг 5. Проверить Worker

9. Открываю в браузере `https://sevastopol-suggest.<мой-сабдомен>.workers.dev`.
   Должна появиться страница «✓ Сервис заявок Sevastopol AI работает».
10. Открываю мою форму
    https://yurich-citycode.github.io/SevastopolAIbot/suggest.html, заполняю
    её и нажимаю «Отправить». Заявка должна прийти мне в личку.

### Шаг 6. Подключить адрес к форме

11. Копирую адрес моего Worker, например
    `https://sevastopol-suggest.your-name.workers.dev`.
12. В репозитории открываю `suggest.html`, нахожу строку:

    ```js
    var WORKER_URL = "__WORKER_URL__";
    ```

    и указываю настоящий адрес:

    ```js
    var WORKER_URL = "https://sevastopol-suggest.your-name.workers.dev";
    ```

    Я могу изменить файл прямо на GitHub: открыть файл → карандаш → Commit.
    GitHub Pages обычно обновляет страницу через минуту-две.

> Пока я не указал адрес в `WORKER_URL`, форма не ломается: она включает резервный
> режим и предлагает скопировать текст заявки, чтобы отправить его мне через бот.

## Деплой через wrangler

Если я работаю из консоли, запускаю так:

```bash
cd worker
npx wrangler login
npx wrangler secret put BOT_TOKEN     # токен основного бота от @BotFather
npx wrangler secret put ADMIN_ID      # мой Telegram ID
npx wrangler deploy
```

Cloudflare хранит секреты в зашифрованном виде. В `wrangler.toml` и в git их
нет. Список секретов я проверяю командой `npx wrangler secret list` — значения
при этом не показываются.

Если я меняю токен, сначала отзываю старый через `/revoke` у @BotFather, затем
снова выполняю `npx wrangler secret put BOT_TOKEN`. Подробные правила хранения
секретов я описал в корневом [SECURITY.md](../SECURITY.md).

Обязательные поля формы — название и адрес. Остальные поля я получаю, если

Фото и геоточку можно прислать мне позже ответным сообщением.

## Как я проверяю и устраняю проблемы

Сначала я открываю адрес Worker в браузере. Если появляется страница «Сервис
заявок Sevastopol AI работает», сам Worker отвечает. Затем я отправляю тестовую
заявку через `suggest.html` и проверяю, что сообщение пришло мне в Telegram.

Для проверки POST-запроса из консоли я могу использовать такой тест:

```bash
curl -i -X POST "https://sevastopol-suggest.<мой-сабдомен>.workers.dev" \
  -H 'Content-Type: application/json' \
  --data '{"name":"Тестовое место","category":"Кафе","address":"Севастополь","description":"Проверка формы"}'
```

Ожидаемый ответ — JSON `{"ok":true}`, после чего тестовое сообщение приходит
мне в Telegram. Я удаляю его из переписки или помечаю как проверочное.

Если что-то не работает, я проверяю:

- `server_not_configured` — в настройках Worker ещё нет `BOT_TOKEN` или `ADMIN_ID`. Я добавляю оба секрета и снова нажимаю **Deploy**.
- `name_and_address_required` — в тесте или форме не заполнено название либо адрес.
- `bad_json` — запрос отправлен не как JSON с заголовком `Content-Type: application/json`.
- `too_many_requests` — с одного адреса уже отправлено больше пяти заявок за час. Я жду или проверяю с другого адреса.
- `telegram_error` — проверяю, что `BOT_TOKEN` относится к моему основному боту, `ADMIN_ID` указан без лишних пробелов, а бот уже запускался и может написать мне.
- форма ничего не отправляет — проверяю `WORKER_URL` в `suggest.html`, что в нём стоит полный адрес с `https://`, и что GitHub Pages уже обновился.
- форма перешла в резервный режим — это значит, что адрес пустой или Worker недоступен. Я могу временно отправить скопированный текст через `@SevastopolAiBot`, а затем проверить адрес Worker.

Логи я смотрю в Cloudflare: **Workers & Pages → мой Worker → Logs → Begin log
stream**. После изменения секретов или кода я заново нажимаю **Deploy**, затем
повторяю проверку формы.
